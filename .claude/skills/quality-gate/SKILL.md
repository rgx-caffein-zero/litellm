# 品質ゲートとセルフレビュー

## 1. 自動修正

```sh
scripts/harness/check.sh fix
```

フォーマッタによる変更は、内容を確認してから残してください。

## 2. 品質ゲート

```sh
scripts/harness/check.sh
```

失敗した場合:

- エラーメッセージを読み、**根本原因** を直す。
- テストの削除・スキップ、期待値の書き換え、ルールの無効化、抑制コメントでは通さない。
- 失敗が自分の変更と無関係なら（変更前から失敗していたなど）、直さずに報告する。`git stash` で変更前の状態を確認すると判断しやすい。
- `skip` になったステップがある場合は、`scripts/harness/detect.sh` で理由を確認し、必要なら報告する。

## 3. セルフレビュー

差分全体を読み直します。

```sh
git diff --stat "$(git merge-base HEAD main)"
git diff "$(git merge-base HEAD main)"
```

`docs/harness/REVIEW_CHECKLIST.md` に沿って確認し、特に次の点を見てください。

- [ ] 目的と無関係な変更が混ざっていない
- [ ] デバッグ用の出力、コメントアウトしたコード、不要になったコードが残っていない
- [ ] 名前とコメントが最終的な実装と一致している
- [ ] 振る舞いの変更にテストがある
- [ ] 追加した抑制コメントには理由が書かれている
- [ ] 利用者に見える変更がドキュメントに反映されている

問題を見つけたら直し、手順 2 からやり直してください。

## 4. 結果の報告

```
## 品質ゲート
| step | result |
| --- | --- |
| format | pass |
| ... | ... |

## セルフレビューで修正した点
- ...

## 残っている懸念
- ...
```
