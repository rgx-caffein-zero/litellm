# 完了の定義（Definition of Done）

次のすべてを満たしたとき、そのタスクは「完了」です。1 つでも満たさない場合は、未完了として報告してください。

## 必須

- [ ] 要求（受け入れ基準）をすべて満たしている。
- [ ] `scripts/harness/check.sh` がすべて成功する（skip されたステップがあれば、その理由を説明できる）。
- [ ] 振る舞いの変更にテストがあり、バグ修正には再現テストがある。
- [ ] 依頼範囲外の変更が含まれていない。
- [ ] 独立レビューで `[must]` 指摘が残っていない。
- [ ] 秘密情報・デバッグ用出力・コメントアウトしたコードが残っていない。
- [ ] 新しく追加した抑制コメントに理由が書かれ、完了報告に列挙されている。

## 該当する場合

- [ ] 利用者に見える変更が README・ドキュメントに反映されている。
- [ ] 公開 API・データ形式・設定の変更について、互換性と移行方法が記載されている。
- [ ] 重要な設計判断が ADR（`docs/adr/`）に記録されている。
- [ ] 新しい依存の追加理由が PR に書かれている。
- [ ] データベースのマイグレーションがある場合、ロールバック手順がある。
- [ ] `CHANGELOG.md` を運用している場合、更新されている。

## コミットと PR

- [ ] コミットメッセージが `docs/harness/COMMIT_CONVENTION.md` に従っている。
- [ ] 各コミットが単独でビルド・テストを通る。
- [ ] PR の説明が `.github/pull_request_template.md` の項目を埋めている。
